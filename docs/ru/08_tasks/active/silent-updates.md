# Тихие обновления приложения

## Описание задачи

Реализовать систему автоматических обновлений приложения Timeline Studio, которая будет работать в фоновом режиме без прерывания работы пользователя.

## Цели

1. **Автоматическая проверка обновлений** - периодическая проверка наличия новых версий
2. **Фоновая загрузка** - скачивание обновлений без влияния на производительность
3. **Умная установка** - установка обновлений в подходящий момент
4. **Откат при ошибках** - возможность вернуться к предыдущей версии

## Технические требования

### 1. Проверка обновлений
- Использование Tauri Updater API
- Проверка каждые 4 часа или при запуске приложения
- Возможность ручной проверки через UI
- Уведомления о доступных обновлениях

### 2. Загрузка обновлений
- Фоновая загрузка с низким приоритетом
- Индикация прогресса загрузки
- Пауза загрузки при активной работе (рендеринг, экспорт)
- Возобновление после сбоев

### 3. Установка обновлений
- Автоматическая установка при закрытии приложения
- Опция "Обновить и перезапустить"
- Сохранение состояния перед обновлением
- Восстановление состояния после перезапуска

### 4. Безопасность
- Проверка цифровой подписи обновлений
- Создание резервной копии перед обновлением
- Механизм отката при ошибках
- Логирование процесса обновления

## Реализация

### 1. Сервис обновлений
```typescript
// src/features/updates/services/update-service.ts
class UpdateService {
  // Проверка обновлений
  async checkForUpdates(): Promise<UpdateInfo | null>
  
  // Загрузка обновления
  async downloadUpdate(
    onProgress: (progress: number) => void
  ): Promise<void>
  
  // Установка обновления
  async installUpdate(): Promise<void>
  
  // Откат обновления
  async rollbackUpdate(): Promise<void>
}
```

### 2. State Machine для управления процессом
```typescript
const updateMachine = createMachine({
  id: 'update',
  initial: 'idle',
  states: {
    idle: {
      on: { CHECK: 'checking' }
    },
    checking: {
      invoke: {
        src: 'checkForUpdates',
        onDone: [
          { target: 'available', cond: 'hasUpdate' },
          { target: 'idle' }
        ],
        onError: 'error'
      }
    },
    available: {
      on: { 
        DOWNLOAD: 'downloading',
        DISMISS: 'idle'
      }
    },
    downloading: {
      invoke: {
        src: 'downloadUpdate',
        onDone: 'ready',
        onError: 'error'
      }
    },
    ready: {
      on: {
        INSTALL: 'installing',
        POSTPONE: 'idle'
      }
    },
    installing: {
      invoke: {
        src: 'installUpdate',
        onDone: 'completed',
        onError: 'rollback'
      }
    },
    rollback: {
      invoke: {
        src: 'rollbackUpdate',
        onDone: 'error'
      }
    },
    completed: {
      type: 'final'
    },
    error: {
      on: { RETRY: 'idle' }
    }
  }
})
```

## Тестирование

### Сценарии тестирования
1. **Успешное обновление**
   - Проверка → Загрузка → Установка → Перезапуск

2. **Обновление с ошибкой**
   - Сбой загрузки → Повтор
   - Сбой установки → Откат

3. **Прерывание процесса**
   - Закрытие приложения во время загрузки
   - Отмена обновления пользователем

4. **Краевые случаи**
   - Нет интернета
   - Недостаточно места на диске
   - Поврежденный файл обновления

## Метрики успеха

1. **Технические метрики**
   - Успешность обновлений > 95%
   - Время простоя < 30 секунд
   - Размер обновлений (дельта vs полные)

2. **Пользовательские метрики**
   - Процент пользователей на последней версии
   - Количество отказов от обновлений
   - Обратная связь о процессе

## Риски и митигация

1. **Риск: Поломка приложения после обновления**
   - Митигация: Автоматический откат, резервные копии

2. **Риск: Прерывание работы пользователя**
   - Митигация: Умное планирование, уведомления

3. **Риск: Большой размер обновлений**
   - Митигация: Дельта-обновления, сжатие

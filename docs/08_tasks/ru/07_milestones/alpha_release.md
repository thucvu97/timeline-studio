# Timeline Studio - Alpha Release v0.60.0

## 🎯 Цель альфа-релиза

Создать минимально работающую версию Timeline Studio с базовыми функциями AI для тестирования на реальных данных с использованием бесплатных локальных моделей.

- **Версия**: 0.60.0-alpha
- **Дата релиза**: Декабрь 2024
- **Статус**: В разработке
- **Текущая версия**: 0.59.8

## 🚀 Основные функции альфа-релиза

### ✅ Готово к использованию

1. **Базовая архитектура**
   - ✅ Tauri v2 интеграция
   - ✅ Next.js 15 с React 19
   - ✅ XState для управления состоянием
   - ✅ Многоязычная поддержка (10 языков)

2. **Медиа обработка**
   - ✅ FFmpeg интеграция
   - ✅ Базовый video player
   - ✅ Timeline редактор
   - ✅ Медиа браузер

3. **AI интеграция (NEW)**
   - ✅ Ollama сервис для локальных моделей
   - ✅ Поддержка быстрых моделей (Llama 3.2, Phi-3, Gemma 2)
   - ✅ AI Content Intelligence модуль
   - ✅ Конфигурация для альфа-тестирования

### 🔧 Минимальный функционал для альфы

1. **AI анализ видео**
   - Детекция сцен (через Ollama)
   - Определение ключевых моментов
   - Генерация тегов и описаний
   - Экспорт результатов в JSON

2. **Субтитры и транскрипция**
   - Базовая генерация субтитров
   - Простая сегментация текста
   - SRT/VTT экспорт

3. **Локальная обработка**
   - Работа без интернета
   - Использование Ollama API
   - Кэширование результатов

## 🛠 Технические требования

### Системные требования
```bash
# macOS / Linux / Windows
- Node.js 18+
- Bun 1.0+
- Rust 1.81+
- FFmpeg 6.0+
- ONNX Runtime (опционально)
```

### Установка Ollama
```bash
# macOS
brew install ollama
ollama serve

# Linux
curl -fsSL https://ollama.ai/install.sh | sh
ollama serve

# Windows
# Скачать с https://ollama.ai/download/windows
```

### Рекомендуемые модели для альфы
```bash
# Самая маленькая и быстрая (400MB)
ollama pull qwen2.5:0.5b

# Оптимальная для большинства задач (1.6GB)
ollama pull gemma2:2b

# Лучшая производительность (2GB)
ollama pull llama3.2

# Для анализа изображений (7GB, опционально)
ollama pull llama3.2-vision
```

## 📦 Установка и запуск

### 1. Клонирование и установка зависимостей
```bash
git clone https://github.com/chatman-media/timeline-studio.git
cd timeline-studio
bun install
```

### 2. Настройка окружения
```bash
# Создать .env.local
cp .env.example .env.local

# Для macOS - автоматическая загрузка переменных
source .env.macos  # опционально
```

### 3. Запуск Ollama
```bash
# В отдельном терминале
ollama serve

# Проверка доступности
curl http://localhost:11434/api/tags
```

### 4. Запуск приложения
```bash
# Режим разработки
bun run tauri dev

# Сборка для продакшена
bun run tauri build
```

## 🧪 Тестовые сценарии

### Сценарий 1: Анализ видео
1. Запустить приложение
2. Загрузить тестовое видео (< 5 минут)
3. Перейти в AI Content Intelligence
4. Нажать "Анализ"
5. Проверить результаты детекции сцен
6. Экспортировать в JSON

### Сценарий 2: Генерация субтитров
1. Загрузить видео с речью
2. Использовать Whisper для транскрипции (если доступен)
3. Сгенерировать субтитры через Ollama
4. Проверить тайминги
5. Экспортировать в SRT

### Сценарий 3: Пакетная обработка
1. Загрузить 3-5 видео файлов
2. Запустить пакетный анализ
3. Проверить параллельную обработку
4. Экспортировать результаты

## 🐛 Известные проблемы

### Критические
1. **TypeScript ошибки** (~2000)
   - Временно отключена проверка типов в CI
   - Не влияет на функциональность
   - Планируется исправить в beta

2. **Производительность Ollama**
   - Первый запрос медленный (загрузка модели)
   - Рекомендуется предзагрузка моделей

### Некритические
1. Отсутствует GPU ускорение для некоторых моделей
2. Нет стриминга ответов в UI
3. Базовая обработка ошибок

## 📝 Инструкция для тестировщиков

### Подготовка
1. Установить Ollama и скачать хотя бы одну модель
2. Подготовить 3-5 тестовых видео (разные форматы)
3. Освободить минимум 5GB места на диске

### Что тестировать
1. **Базовый флоу**: загрузка → анализ → экспорт
2. **Производительность**: время обработки, использование памяти
3. **Стабильность**: работа с разными форматами видео
4. **AI качество**: релевантность результатов анализа

### Как репортить баги
1. Создать issue на GitHub
2. Приложить логи из консоли
3. Указать версию Ollama и модель
4. Описать шаги воспроизведения
